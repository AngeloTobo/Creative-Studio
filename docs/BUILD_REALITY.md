- Project-scoped CreativeDNA, queues, libraries, artifacts, and portal summaries.

The Generate surface exposes the same safe scalar controls, saves changed values as a new immutable revision, and queues that exact returned revision in one action.
- Local Runner 1.4 enrollment creates a 256-bit one-time token, stores only its SHA-256 hash in D1, and exposes revocation plus live machine/ComfyUI state through the real Settings surface. The separate runner hostname serves only eleven bearer-authenticated generation, media, and training routes and returns `404` for its shell or owner APIs.
- Cloudflare Free request pressure is bounded in source: one browser snapshot replaces twelve parallel reads, real-browser polling runs at most once per minute only for active work in a visible tab, the Local Runner uses one unified claim or combined active heartbeat per minute, the recovery cron is hourly, Queue retries are capped at three, and `npm run check:cloudflare-free` enforces a maximum 2,904-request/day baseline before explicit actions or active Queue deliveries.
- Local-first mode launches Vite, a Wrangler-local BFF, local D1/R2 state, and a separately enrolled Local Runner in one `npm run local` command. Its active browser refreshes every two seconds and its runner claims every five seconds, but both paths remain on `127.0.0.1` and consume no Cloudflare allowance. The local BFF refuses image/music generation without a real imported ComfyUI workflow, labels AFDFW remote-only, and retains real results locally with their complete settings stamps.
- API-format image, music/audio, and video workflows can create `local-comfyui` jobs from the consolidated CreativeDNA Generate surface. Each job stamps the exact workflow/revision/hash, safe parameter values, detected models, and media-parameter bindings. Compatible retained generated artifacts can be selected alongside retained uploads, with normalized source type and artifact lineage preserved.
- The Windows runner downloads only the bound owner inputs, uploads them to localhost ComfyUI, submits the immutable graph, persists the ComfyUI prompt ID, renews a two-minute lease, survives browser closure, and resumes an existing prompt after an agent restart instead of resubmitting it. Busy-history timeouts are treated as transient, and eligible retry jobs preserve an already-submitted prompt rather than duplicating GPU work.
- Generation jobs now retain their actual execution start plus explicit queue, provider-queue, input-preparation, submission, render, output-download, retention, and terminal stages. A 20-minute awareness threshold creates a Production inbox warning and opens evidence in Queue without cancelling local ComfyUI; the existing 15-second history-request timeout remains a transient poll and the 24-hour local safety window remains the only runner render cutoff.
- Generate and Queue derive a compact performance profile from the immutable settings stamp: exposed dimensions/megapixels, steps, frames, duration, batch, models, retained inputs, and prompt length. Completed jobs from the exact workflow revision provide measured median and fastest execution times. Likely workload contributors are labeled as inferences, prompt length is not blamed by default, and missing provider settings are reported as unavailable rather than estimated.
- Modality-specific save nodes are preferred when selecting ComfyUI history output, preventing a preview file from being retained when the graph has an intended save node.
- Runner completion accepts only allowlisted image/audio/video outputs up to 100 MB, stores them at a deterministic Creative Studio R2 artifact key, verifies exact byte size, and only then completes the job and creates its CreativeDNA training candidate. Retained video has native playback and download review.
- Each uploaded asset records explicit CreativeDNA-training eligibility and owner provenance. Upload does not start training; the owner explicitly selects consented uploads and starts a separate durable training run.
- Upload-based CreativeDNA training jobs persist their exact asset IDs, accepted prompt/settings evidence, optional base-DNA lineage, target modality, idempotency key, runner identity, result DNA ID, and terminal state. Local Runner 1.4 claims an exact owner-scoped bundle under a renewable two-minute lease, measures real image pixels and decoded audio/video samples locally, and runs the bundled Gemma 4 multimodal ComfyUI workflow against every selected upload. Each image, audio, or video source keeps a detailed reusable description plus the exact model, analysis prompt, workflow version, ComfyUI prompt ID, and inference settings. Deterministic measurements and retained prompt/settings evidence remain the bounded authority for source metrics and dimension synthesis. The Worker canonicalizes every source from D1, requires complete description provenance for v1.1 results, preserves commercial-reference rights from an optional base version, and rejects incomplete or foreign evidence. Cancellation and failure remain explicit.
- CreativeDNA training Phase 1 is deterministic evidence/profile synthesis; it does not modify model weights or claim LoRA/foundation-model fine-tuning.
- CreativeDNA training Phase 2 adds a mandatory trained-version review gate. The workspace compares baseline and trained directives, all eight dimension changes, per-dimension confidence, source observations, and bounded source metrics. Approve and reject both require a note. Decisions are append-only with actor, timestamp, and post-decision active DNA; approval activates the exact immutable result, while rejection leaves the current active DNA unchanged or restores the recorded baseline when rejecting an active result.
- CreativeDNA Phase 3 adds a project-scoped production-loop read model derived by the Worker from durable DNA, generation, artifact, decision, training-evidence, training-job, and training-review records. Its explicit next action moves through blueprint, production, retained-output review, fresh evidence, training, and trained-version review without relying on browser-local progress.
- Accepted prompt/settings evidence is automatically eligible for the next training version exactly once across waiting, running, and completed jobs. A D1 uniqueness reservation closes concurrent-request races. Failed or cancelled training atomically releases the evidence; the UI shows fresh and already-captured counts instead of silently adding the same result again.
- CreativeDNA Phase 4 adds a Worker-derived, cross-project Production cockpit with an owner action inbox, shell notifications, active/failed run totals, queue positions, execution durations, 20-minute long-run warnings, workflow and DNA lineage, artifact decisions, retained byte/file totals, and Local Runner device/heartbeat/error state. Its project, modality, workflow, DNA, and decision filters operate on one durable read model rather than browser-local counters.
- Cockpit actions route directly to the exact trained-version review, artifact review, failed run, or Runtime surface. A generation recovery creates a new retry job and focuses it in Queue while retaining the failed run in history; a failure with an existing retry is treated as resolved instead of becoming a permanent notification.
- Saving a manual CreativeDNA version atomically records it as the project-active version, so a reload cannot fall back to an older trained baseline.
- Pending or rejected trained DNA remains visible for inspection and history but cannot generate, seed retry/reuse, become a child-version parent, or serve as another training baseline. The Worker enforces these rules independently of the browser, and generation defaults only to a manual or approved version.
- Deterministic CreativeDNA compilation, bounds, prompt translation, rights-safe provenance, root/parent/version lineage, and both music/image submission.
- Queue-owned production submission and per-generation reconciliation continue after the originating browser request ends; a scheduled recovery sweep re-enqueues due work.
- D1-backed idempotency, reconciliation leases, a 30-minute timeout, bounded retries, retry lineage, unique artifact creation, and explicit cancel controls.
- Every real upstream completion enters a non-cancellable `retaining` state, streams to a deterministic Creative Studio R2 key, verifies stored size, and becomes completed/ready only after that verification. Interrupted retention retries without resubmitting generation.
- Media-aware artifact review: retained music uses a real audio player and download, retained images open into a full-size inspector, and retained R2 artifact responses support byte-range playback and seeking.
- Accept and reject require a bounded review note in the UI, typed adapter boundary, and Worker. Append-only decision history visibly includes decision, note, actor, and timestamp; archive still permits an optional note.
- Artifact history, lineage expansion, explicit accept/reject/archive controls, and failure cards that preserve the raw provider error while adding actionable recovery guidance and a durable retry action.
- Every new generation job and artifact carries an immutable settings stamp. Reuse creates a new job from the recorded prompt, provider, and settings and records its source job instead of mutating history.
- Every completed result creates a CreativeDNA training candidate containing the output artifact, prompt, and settings stamp. Accept promotes it to `training-ready`; reject marks it `excluded`; archive does not silently change its training judgment.
- Exact AFDFW method/path allowlist with no generic proxy.
- Same-account AFDFW service binding for identity handoff and generation; CreativeDNA remains product-owned in Creative Studio D1.
- Accept, reject, and archive are decision-only operations for real results because retention is completed first; an interactive review request also repairs an older pending-retention artifact before recording a decision.
- Fail-closed browser/Worker environment validation and a production-readiness preflight.
- Workers-runtime Vitest integration using the real D1 migrations and production Worker entrypoint.
